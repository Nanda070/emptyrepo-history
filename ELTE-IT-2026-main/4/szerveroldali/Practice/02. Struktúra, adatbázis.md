# Серверное веб-программирование - 02.

## Laravel
PHP-фреймворк для разработки веб-приложений с архитектурой MVC.

### MVC (Модель-Представление-Контроллер)
Шаблон проектирования ПО, разделяющий программу на три компонента:
![Схема MVC](https://i.imgur.com/pQXX5l8.png)

- **Модель (Model):** бизнес-логика приложения
- **Представление (View):** внешний вид/интерфейс приложения
- **Контроллер (Controller):** связующее звено, отвечающее за взаимодействие между моделью и представлением

### Установка
Если вы использовали [установщик](https://github.com/totadavid95/PhpComposerInstaller), созданный Tóta Dávid, то никаких дополнительных действий не требуется. В случае индивидуальной установки PHP и Composer следуйте вручную [инструкции по установке](https://github.com/totadavid95/PhpComposerInstaller#manual-installation-on-windows).

## База данных

### [Миграции (Migrations)](https://laravel.com/docs/10.x/migrations)
Определяют структуру базы данных. Это сгенерированные файлы, их имена всегда используют следующий формат:
```
<timestamp>_<action>_<table_name>_table
```
Например: `2014_10_12_000000_create_users_table`. Временная метка (timestamp) определяет порядок выполнения миграций при вызове команды `php artisan migrate`. Каждая миграция является наследником класса `Migration` и имеет два метода: `up()` и `down()`.

```php
return new class extends Migration {
    /**
     * Запуск миграций.
     */
    public function up(): void {
        Schema::create('users', function (Blueprint $table) {
            $table->id();
            $table->string('name');
            $table->string('email')->unique(); // уникальное поле
            $table->timestamp('email_verified_at')->nullable(); // поле может содержать null
            $table->string('password');
            $table->rememberToken();
            $table->timestamps();
        });
    }

    /**
     * Откат миграций.
     */
    public function down(): void {
        Schema::dropIfExists('users');
    }
};
```
Миграции — это, по сути, система контроля версий для структуры базы данных приложения.

### Eloquent API
Laravel предоставляет объектно-реляционное отображение (Object-Relational Mapping, ORM), которое позволяет взаимодействовать с базой данных единым образом, игнорируя особенности конкретных СУБД.

Это делает разработку очень удобной, так как изменив всего одну строчку настройки, мы можем переключить СУБД, с которой работает приложение.

Подробнее об этом позже.

### Настройка базы данных
`MySQL -> sqlite`
В файле `.env` строки:
```dotenv
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=laravel
DB_USERNAME=root
DB_PASSWORD=
```
нужно заменить на:
```dotenv
DB_CONNECTION=sqlite
```
Этого достаточно, так как Laravel автоматически определит путь к базе данных (базы данных SQLite — это просто локально сохраненные файлы). Если проверить в `php artisan tinker` (`env('DB_DATABASE')`), то видно, что имя базы данных не задано. В файле `config/database.php` мы можем увидеть:
```php
'sqlite' => [
    'driver' => 'sqlite',
    'url' => env('DATABASE_URL'),
    'database' => env('DB_DATABASE', database_path('database.sqlite')),
    'prefix' => '',
    'foreign_key_constraints' => env('DB_FOREIGN_KEYS', true),
],
```
что значением ключа `database` является либо заданное в `.env`, либо запасной вариант (fallback), которым в нашем случае является файл `database_path('database.sqlite')`. Этот файл еще не существует, но его можно создать, выполнив команду:
```shell
php artisan migrate
```

### Сидеры и Фабрики (Seeder, Factory)
С помощью миграций мы создали базу данных с определенной структурой. Однако данных в ней нет, а для тестирования ПО они необходимы. Для их генерации мы можем определить сидеры.
`database/seeders/DatabaseSeeder.php`
```php
class DatabaseSeeder extends Seeder {
    /**
     * Заполнение базы данных приложения.
     */
    public function run(): void {
        // \App\Models\User::factory(10)->create();

        // \App\Models\User::factory()->create([
        //     'name' => 'Test User',
        //     'email' => 'test@example.com',
        // ]);
    }
}
```
Здесь идет обращение к методу `factory` класса `User`.

`database/factories/UserFactory.php`
```php
class UserFactory extends Factory {
    /**
     * Определение состояния модели по умолчанию.
     * @return array<string, mixed>
     */
    public function definition(): array {
        return [
            'name' => fake()->name(),
            'email' => fake()->unique()->safeEmail(),
            'email_verified_at' => now(),
            'password' => '$2y$10$92IXUNpkjO0rOQ5byMi.Ye4oKoEa3Ro9llC/.og/at2.uheWG/igi', // password
            'remember_token' => Str::random(10),
        ];
    }

    /** Указать, что email адрес модели должен быть неподтвержденным. */
    public function unverified(): static {
        return $this->state(fn (array $attributes) => [
            'email_verified_at' => null,
        ]);
    }
}
```
Фабрика создает представление для конкретной модели со случайными (fake) тестовыми данными.

Заполнить базу данных тестовыми данными можно с помощью команды:
```shell
php artisan db:seed
```

Команда:
```shell
php artisan migrate:fresh --seed
```
удаляет все существующие данные, заново выполняет миграции и генерирует свежие тестовые данные.
