# Отношения между моделями, заполнение базы данных (seed)
## Повторение
Рекомендуется ознакомиться: [Horváth Győző: Laravel — Отношения между моделями (венг.)](http://webprogramozas.inf.elte.hu/#!/subjects/webprog-server/handouts/laravel-04-rel%C3%A1ci%C3%B3k)

На прошлом занятии мы написали миграции для классов `Category` и `Post`, в которых указали следующее:

`database/migrations/...create_posts_table.php`:
```php
$table->unsignedBigInteger('author_id')->nullable();
$table->foreign('author_id')->references('id')->on('users')->onDelete('cascade');
```
Это означает, что мы определили внешний ключ `author_id`, который ссылается на поле `id` таблицы `users`. При удалении пользователя (`User`) соответствующий пост (`Post`) также будет удален (каскадное удаление). Это создает связь между двумя моделями в базе данных, однако её также необходимо отразить в самих классах моделей.

Определим связь между `Post` и `User` (много постов к одному пользователю, `Post` N : 1 `User`)
`app/Models/Post.php`:
```php
public function author(): BelongsTo {
	// По умолчанию Laravel искал бы внешний ключ user_id, поэтому мы вручную указываем имя author_id
	return $this->belongsTo(User::class, 'author_id');
}
```

`app/Models/User.php`:
```php
public function posts() {
	return $this->hasMany(Post::class);
}
```

После определения этих методов мы можем получать посты пользователя через `$user->posts`, а автора поста — через `$post->author`.

## Создание связи «многие ко многим» (N : M)
Отношение «многие ко многим» требует создания связующей (промежуточной) таблицы. Первым делом создадим миграцию для структуры связующей таблицы. Обратите особое внимание на название (по правилам Laravel оно формируется из имен связываемых моделей в единственном числе, в алфавитном порядке):
```shell
php artisan make:migration create_category_post_table
```
В созданный файл миграции `database/migrations/...create_category_post_table.php` добавим следующие настройки:
```php
public function up(): void  {
	Schema::create('category_post', function (Blueprint $table) {
		$table->id();
		$table->unsignedBigInteger('category_id'); // первая таблица
		$table->unsignedBigInteger('post_id'); // вторая таблица
		$table->timestamps();
		
		$table->unique(['category_id', 'post_id']);
		$table->foreign('category_id')->references('id')->on('categories')->onDelete('cascade');
		$table->foreign('post_id')->references('id')->on('posts')->onDelete('cascade');
	});
}
```
Затем укажем связь в классах моделей:

`app/Models/Post.php`:
```php
public function categories() {
	// Сохраняем временные метки (timestamps) в связующей таблице
	return $this->belongsToMany(Category::class)->withTimestamps();
}
```
`app/Models/Category.php`:
```php
public function posts() {
	return $this->belongsToMany(Post::class)->withTimestamps();
}
```

Метод `belongsToMany` по умолчанию не записывает временные метки в связующую таблицу, поэтому мы явно вызываем метод `withTimestamps()`.

## Заполнение тестовыми данными (Seed)
Для начала расширим фабрику постов `database/factories/PostFactory.php`:

```php
public function definition(): array {
	return [
	// Заголовок в виде предложения без точки в конце
	'title' => Str::of(fake()->sentence())->rtrim('.'),
	// Генерация от 1 до 5 абзацев. Второй параметр true указывает,
	// что нужно вернуть единую строку, а не массив строк
	'content' => fake()->paragraphs(rand(1, 5), true)
	];
}
```
Теперь фабрики для всех необходимых моделей готовы.

`database/seeders/DatabaseSeeder.php`:
```php
<?php

namespace Database\Seeders;

// use Illuminate\Database\Console\Seeds\WithoutModelEvents;
use Illuminate\Database\Seeder;
use App\Models\User;
use App\Models\Category;
use App\Models\Post;

class DatabaseSeeder extends Seeder
{
	/** Заполнение базы данных приложения. */
	public function run(): void {
		$userCount = rand(5, 10);
		$users = User::factory($userCount)->create();
		// Сохраняет вставленные в БД модели в виде коллекции (Collection)
		
		$categoryCount = rand(8, 15);
		$categories = Category::factory($categoryCount)->create();
		
		$postCount = $categoryCount * rand(6, 7);
		$posts = Post::factory($postCount)->create();
		
		// Обход коллекции posts, доступ к переменным внешнего контекста через use:
		$posts->each(function(Post $post) use (&$users, &$categories, &$categoryCount) {
			// Установление связи: связываем пост со случайным пользователем
			$post->author()->associate($users->random()->id);
			$post->save(); // Изменения метода associate необходимо зафиксировать через save()
			
			// Установление связи N:M с категориями через метод sync
			$post->categories()->sync($categories->random(rand(0, $categoryCount)));
		});
	}
}
```
После этого с помощью команды:
```shell
php artisan migrate:fresh --seed
```
базу данных можно заново пересоздать и заполнить тестовыми данными.
