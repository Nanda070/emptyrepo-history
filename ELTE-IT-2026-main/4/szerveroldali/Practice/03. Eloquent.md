# Eloquent API
**Объектно-реляционное отображение** (ORM — Object-Relational Mapper) — это API, которое связывает таблицы нашей базы данных с объектами моделей.

Давайте рассмотрим класс модели `User`, который был сгенерирован для нас по умолчанию.

Следующие инструкции можно удобно протестировать в консоли `php artisan tinker`.

Включение логирования сгенерированных `SQL`-запросов:
```php
DB::enableQueryLog()
```
Получение лога выполненных запросов:
```php
DB::getQueryLog()
```

## Создание записей
Создание записей с помощью фабрики (Factory) в базе данных:
```php
User::factory()->create(int $amount): Collection|User
```

Генерация моделей с помощью фабрики в памяти (без сохранения в базу данных):
```php
User::factory()->make(int $amount): Collection|User
```

Мы можем переопределить значения по умолчанию при создании через фабрику:
```php
User::factory()->make(['name' => 'имя'])
```
В этом случае у созданной модели поле `name` будет равно `'имя'`.

Создание объекта через конструктор и сохранение в базу данных:
```php
$user = new User();
$user->name = 'имя';
$user->email = 'test@szerveroldali.hu';
// $user->password = '12345678';
$user->password = bcrypt('12345678');
$user->remember_token = Str::random(10);
$user->save();
```

Более элегантное решение ([массовое заполнение / mass-assignment](https://laravel.com/docs/10.x/eloquent#mass-assignment)):
```php
User::create(['name'     => 'имя',       'email'          => 'test2@szerveroldali.hu',
              'password' => bcrypt('p'), 'remember_token' => Str::random(10)])
```
Это можно использовать только в том случае, если мы указали в модели, какие поля разрешены для массового заполнения (свойство `$fillable`).

## Выборка данных
Получение всех экземпляров данной модели:
```php
User::all(): Collection
```

Получение самой первой записи из базы данных:
```php
User::first(): User
```

Получение модели по её первичному ключу (ID):
```php
User::find($id): ?User;
```
(`?User` означает: возвращается объект типа `User` либо `null`, если запись не найдена.)

Получение нескольких пользователей по списку ID:
```php
User::findMany(array $ids): Collection;
```
Возвращает коллекцию `Collection`. Несуществующие записи просто пропускаются. (Если передать массив в метод `find`, то внутри вызовется именно `findMany`.)

Метод `find`, который в случае неудачи выбрасывает исключение `ModelNotFoundException`:
```php
User::findOrFail($key): User;
```

Получение общего количества моделей:
```php
User::count(): int;
```

Использование условий `WHERE`. Некоторые запросы выполняются не сразу, а возвращают объект `Builder`, для выполнения которого необходимо вызвать метод `get()`.
```php
User::where('id', '>', 5)->get()
```
Мы можем объединять условия в цепочку (chaining):
```php
User::where('id', '>', 18)->where('id', '<', 20)->get()
```
В этом случае между двумя условиями `where()` будет логическое «И» (AND). Для связи «ИЛИ» используйте метод `orWhere(...)`.

Получить SQL-запрос от объекта `Builder` можно с помощью вызова метода `toSql()`.

## Обновление данных (Update)
Изменение полей объекта и сохранение в базу данных:
```php
$user = User::find(1);
$user->email = 'test@test.hu';
$user->save();
```

Или более короткий вариант:
```php
User::find(1)->update(['email' => 'test@test.hu']);
```

## Удаление данных (Delete)
```php
User::destroy(1)
```
Возвращает количество удаленных записей. Можно передать массив для удаления нескольких записей:
```php
User::destroy([1,2,3])
```

## Создание моделей

Создание модели через Artisan:
```shell
php artisan make:model -mf <имя_модели> // ключи -m (migration) и -f (factory)
```
Например:
```shell
php artisan make:model -mf Category
```

При этом создается файл модели `app/Models/Category.php`, файл миграции `database/migrations/<дата>_create_categories_table.php` и класс фабрики `database/factories/CategoryFactory.php`.

Определим структуру таблицы в созданном файле миграции ([доступные типы столбцов](https://laravel.com/docs/10.x/migrations#available-column-types)):
```php
public function up(): void {
    Schema::create('categories', function (Blueprint $table) {
        $table->id(); // автоинкрементное поле BIGINT (8 байт)
        $table->string('name')->unique(); // уникальная строка VARCHAR (256 байт)
        $table->string('style');
        $table->timestamps(); // столбцы created_at и updated_at
    });
}
```

Напишем метод `definition()` для фабрики генерации данных:
```php
public function definition(): array
{
    return [
        'name' => fake()->word(), // название категории — случайное слово
        'style' => fake()->randomElements([
            'primary',
            'secondary',
            'success',
            'warning',
            'info',
            'dark',
            'light'
        ]) // стиль — случайный элемент из данного массива
    ];
}
```

Аналогично создаем модель `Post` (Пост).

Миграция для `Post`:
```php
public function up(): void {
    Schema::create('posts', function (Blueprint $table) {
        $table->id();
        $table->string('title');
        $table->text('content'); // тип TEXT для длинного содержимого
        $table->unsignedBigInteger('author_id')->nullable(); // внешний ключ (может быть null)
        $table->timestamps();

        $table->foreign('author_id')->references('id')->on('users')->onDelete('cascade');
        // столбец author_id ссылается на поле id в таблице users
        // onDelete('cascade') означает, что при удалении пользователя будут удалены и все его посты
    });
}
```
`app/Models/Post.php`:
Определим отношение между `Post` и `User` (много постов к одному пользователю — `Post` N : 1 `User`):
```php
public function author(): BelongsTo {
    // По умолчанию Laravel искал бы внешний ключ user_id, поэтому мы вручную передаем имя столбца author_id
    return $this->belongsTo(User::class, 'author_id');
}
```
